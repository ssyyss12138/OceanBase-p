# 评审体验路线（约 3—5 分钟）

先完成 README 部署、导入、配置和发布，打开导入应用的「运行」页面。

## 初始状态

运行 `python scripts/new_save.py` 生成新存档码，填入 Dify 的「存档码」框。新码代表新玩家，不依赖作者已有数据。记下它；新聊天使用同一码会恢复记忆和状态。

## 路线 A：守约合伙人 + 跨会话记忆

1. 输入「买一瓶勇气汽水」。应获得汽水，欠笑话变成 1，返回账单和记忆保存标识。
2. 当次编一个含独特词语的笑话，例如「讲笑话：一只章鱼拿着【你临时想出的奇怪词】去银行存钱，柜员说我们不收夜宵」。应欠账变为 0。只说“已经讲过了”不算还账。
3. 在 Dify 新建聊天，仍填同一个存档码，询问「我刚才讲的笑话是什么？」生成台词应使用独特细节，记忆账本显示实际读取的旧事。这个步骤不借用旧会话消息完成。
4. 输入「结算离店」，应得到「守约合伙人」。

预期是规则、状态和因果关系一致，具体台词可以不同。接口失败时应出现异常提示，不能认定交易已完成。

## 路线 B、C

分别用新存档码：

- B：买汽水 →「我坦白，我还没准备好兑现承诺」→ 结算；得到「诚实赊账客」。
- C：买汽水 → 直接结算；得到「回声通缉令」。

买汽水后还可买回声糖，验证欠账增加、老板怎样回应累积的承诺。

## 隔离、恢复、异常

- 玩家 B 用新码询问 A 的独特笑话，不能读到 A 的私有记忆。
- 重启 game 和 powercontext 服务，用 A 的码开新聊天，应恢复前面的状态和回忆。
- 私有环境暂时停止 PowerContext 再输入，应提示无法完成；恢复后可重试。
- 同一轮 HTTP commit 重放返回同一结果，不重复结算；由规则测试和真实集成脚本验证。

## 重置与自动验证

用 `python scripts/new_save.py` 生成新码即可重开，不删除其他玩家的数据。

- `scripts/verify_powercontext.py` 验证真实 PowerContext 写读、业务存档重开、隔离及重放。
- `scripts/verify_dify.py` 执行真实 Dify + 已配置 Qwen + PowerContext，检查三结局和新会话台词是否使用真实记忆。

前一项通过不代表完整 Dify 应用已验收。证据应明确记录实际完成的检查。
