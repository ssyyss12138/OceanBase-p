- 报名仓库：`https://github.com/ssyyss12138/OceanBase-p`
- 分支：`gjc-dify`，基于 `2026-competition-ecosystem` 开发。
- Commit ID：填写该分支**已推送且包含本次验收材料的完整 SHA**。本地运行 `git rev-parse HEAD` 可取得；不要填写 FTS 或 AI 函数题的提交。
- 全部交付资产在本目录 `dify/`。DSL 为 `dsl/causal-store.yml`，适用 Dify 1.9.2；从依赖安装到发布入口见 `README.md`。

## 作品评价方向

官方题面列出以下五个维度，但尚未给出具体权重或满分公式。本作品按这些维度交付，不将节点数量或同时使用两种指定技术作为得分依据。

| 维度 | 对应设计与核对方式 |
| --- | --- |
| 创意 | 不收钱只收承诺的便利店；「收据会记仇」通过真实记忆延续，形成可验证的玩法 |
| 趣味与互动 | 自编笑话、累积欠账、坦白或守约，选择产生三种结局，老因围绕玩家自己的内容接梗 |
| 体验与完成度 | 开场说明、示例问题、状态账单、下一步行动和可读旧收据；约 3—5 分钟走完主线，新码可重开 |
| 技术结合 | Dify 编排、Qwen 语义和台词、后端权威规则、PowerContext 长期记忆分工明确；新会话台词使用实际召回细节 |
| 工程与可复现 | 13 项测试、全容器运行、重复结算保护、版本冲突、未完成写入恢复、玩家隔离、真实重启恢复及模型故障路径记录 |

## 证据阅读顺序

1. `evidence/STATUS.md`：实际通过范围与限制。
2. `evidence/dify-e2e.json`：主要玩法、三种结局、新聊天记忆与真实节点记录。
3. `evidence/docker-powercontext-integration.json`：真实 Source、Memory、Context 读写、隔离、重放与不确定写入核对。
4. `evidence/docker-restart.json`：实际重启 game 和 PowerContext 容器后的业务状态与记忆恢复。
5. `evidence/docker-deployment.json`：九项服务状态及配置文件摘要；本次为专用部署累计验收，未声称另建第二套全空栈复测。

截图和录屏不是唯一验证手段，本提交使用真实对话日志、节点记录和集成记录，且提供可运行源码与复现步骤。未提交真实 API Key、管理员密码或作者存档访问码。没有使用模型 Mock 或预录台词作为完整应用成功证据。
